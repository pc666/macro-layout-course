工具从哪里知道数据往哪走？

作者明确写的是，电路设计者提供 dataflow constraint，摆放工具据此建数据流图（DFG）。论文给出了如何使用这份约束；它的文件格式和设计者生成它的过程，文中没有交代。

§ III-A · 图 4

先让 macro 长出一棵树

工具从根出发，沿着每颗 macro 实例名里的斜杠逐层查找。已有的节点复用，缺的节点补上。于是共用路径的 macro 自然共享一段树枝。

为什么要先扫完所有 macro？

树的分叉由 macro 的路径决定。随后才读标准单元的名字，沿现有树往下走，停在能匹配的最深节点。一个模块内部即使有成千上万个标准单元，这一步只需知道它们的面积应归到哪个节点。原文的例子中，macro 是 A1/B1/C1，标准单元是 A1/B1/C4，后者挂在 B1。

§ III-A · 面积预留

沿树向下分，沿路径累加

在教学树中，挂在 B1 的标准单元面积由四颗 SRAM 均分；挂在 N4 的面积只由 s0、s1、s2 均分。每个有面积的节点，都把自己的份额直接分给所有后代 macro 叶子。

如果先把 B1 的面积均分给两个子模块，再让两个模块各自往下分，只有一颗 SRAM 的 N7 就会独得一半。论文按后代 macro 的颗数均摊，所以 N7 只分到四分之一。这个差别会落到每颗 macro 的临时占地上。

为什么这和拥塞有关？

几颗 macro 可能围着同一批标准单元。先把 macro 挤得很紧，后面的标准单元摆放就可能把逻辑挤进小缝，或推远到需要长线连接的位置。作者用临时放大的占地预留空间。面积均摊是一个几何估计，真正的 overflow 仍由后续布线衡量。

§ III-B · 公式 1

哪两组值得先合并？

起初一颗 macro 就是一组。作者采用 best-choice 聚类，用两道硬条件限制谁能合，用四项分数比较合格的候选。合并后，接下来比较的对象就变成了新组。

先看资格

原文实验要求共同层数 H > 2，两组的合计面积 < 0.3 × 允许摆放面积。例如 s0 与 s1 共享 A3/B1/N4，H 为 3；s0 与 s3 只共享 A3/B1，H 为 2，恰好卡在门槛外。虚设的根节点不计层数。

再比较分数

φ = 0.2 / ΔD + 0.3 H
　 + 0.3 C + 0.2 / (ΔA + 1)

ΔD 是初始摆放中两组几何中心的距离，越近得分越高。H 是实例路径开头连续相同的层数。C 是组间连接数，连接越多得分越高。ΔA 是两组面积的差的绝对值，越相似得分越高。这里使用论文实验的权重。

试算第一轮

初始中心放在同一直线，坐标分别为 0、4、10、2。调整下面两个输入，观察哪一对有资格且得分最高。

组对HC面积和得分 φ结果

跟算一次，为什么近的候选也可能输？

取默认 C = 3。s0 与 s1 距离 4、面积相同、有 2 条连接，得分为 0.05 + 0.90 + 0.60 + 0.20 = 1.75。s0 与 s2 距离 10、面积差 4、有 3 条连接，得分为 0.02 + 0.90 + 0.90 + 0.04 = 1.86。多一条连接足以抵消另外两项的损失。把滑块调到 2，就能看到首选改变。

这里的数字能当作工业设计参数吗？

权重与严格不等号出自原文。演示用任意一致的面积和距离单位，并明确用临时占地计算面积项。原文这一节没有完整规定输入归一化、中心重合时的数值保护或候选分数平局时的处理。算例用于理解排序，不能据此复算作者的工业案例。

§ VII-A / C / D · 图 8、9

把已经分好的组放回数据流图

到第 III 节结束，工具已经知道组成员。再读设计者给的约束时，工具可以按实例归属把 macro 组对应到 DFG 的模块节点。一个模块里可以有多个组。

第一次用在分区

假设 N4 的一组在左区，N7 的一组在右区。算法可以给组对加一条加权的虚拟连线，权重包含共同层次和 DFG 关系。左右各换一组时，同时衡量真实信号线的切割数变化和虚拟连线代价的变化。于是，设计者给的 N4 → N7 会实际影响哪个组分到哪边。

N4、N5 之间也很有意思。图中它们都从 N1 接数据，又都送往 N7。论文把这种共同直接上游且共同直接下游的关系也纳入评分，即使两者之间没有直接数据流。一个节点对应许多组时，关系权重按组对数摊分，避免组数多就被重复强调。

第二次用在摆放顺序

排到属于某个 DFG 节点的组，就从那个节点按广度优先遍历，把访问到的节点对应的组加入摆放队列。这次遍历把边视为双向。从 N4 出发，上游 N1 和下游 N7 都是一步邻居。随后才由合法化算法逐颗找坐标。

换一个问题自测：若只有实例名，能走到哪？

有 macro 和标准单元的实例名，可以建层次树；加上单元面积，可以做预留；再有初始位置、面积和连接数，就能按第 III 节评价候选组对。要使用第 VII 节的 N4 → N7，还需设计者给出模块级数据流约束。连接数 C 只是数量，两个方向相反的设计可以得到相同的 C。
