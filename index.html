第 01 课　/　电路入门

一块缓存，四颗 SRAM

CPU 想读地址 17，摆放工具会看到什么？

先跟着一次读数据走。CPU 发来地址，缓存控制器判断该去哪个存储块，把地址送过去。存储块取出数据，再送回控制器。需要连线的这两个东西，在硅上各占一块地方。

从功能走到实物

Cache（缓存）是一项功能，保存可能很快再用的数据。SRAM（静态随机存取存储器）是一种存这些比特的电路。Hard macro（硬宏）是交给这一层摆放工具的物理对象，有做好的内部版图、外形和引脚。

本课的小例子里，数据容量 32 KiB，设计者用四颗 8 KiB 的 SRAM 实现它。四颗会各有一个位置。控制器的组合逻辑和寄存器则由许多小的标准单元组成。这里暂时省略 cache tag 与其他管理信息。

以后在图里看到 A，先问它存什么、谁读写它。答出这两件事，那个长方形就有意义了。

第 02 课　/　电路入门

哪些模块里的宏多

看到一个模块名字，怎么猜里面大致有什么？

先找大块反复读写的数据，再确认这些数据最终映射成了什么。同一段 RTL 换一套库、综合选项或层次边界，交给 pack 的宏清单可能就变了。

CPU 的 L1、L2 缓存
通常有数据数组、存地址标签的 tag 数组，以及控制逻辑。为满足容量、位宽、端口和频率，数组可能切成多个 bank（可以分开访问的分区），一个 bank 还可能拼多颗 SRAM。
AI 加速器和片上缓冲
权重、输入和中间结果都要暂存。较大的 scratchpad（由软件或控制器明确管理的片上存储）常见多颗 SRAM。计算阵列本身也可能硬化成宏。
译码器、仲裁器、状态机
主要做判断、选择、记少量状态，通常以标准单元为主。一个小 FIFO 可以用触发器实现，也可以映射到存储宏，要看深度与实现库。
PLL、模拟接口、SerDes
PLL 产生或调整时钟。SerDes 收发高速串行数据。实现可能作为已定版图的 IP 整块交付。主关切分别可能是时钟噪声、供电和靠近芯片接口。

数的是哪个层级？

子模块内部有 30 颗 SRAM。如果整个子模块已经硬化，顶层可能只看到一个大宏。做宏清单时记录三列就够起步：实例路径、引用的模板、它在当前层能否移动。

把团队的一颗宏查到底

找一颗 SRAM，记录深度、位宽、读写端口和延时。深度 256、位宽 16 bit 的逻辑阵列可存 4,096 bit，即 512 B。容量不能直接推出物理面积，面积还取决于位单元、端口和外围读写电路。

第 03 课　/　电路入门

一颗宏需要哪些文件

同样叫 SRAM，工具怎么知道它有多宽、哪个脚接数据？

把工程文件想成回答不同问题的几份图纸。面对一个完全陌生的 block，先凑齐前四项，就能读懂初始盘面。

网表 / netlist
列出实例和网络。实例是某一颗具体的 SRAM；网络把驱动引脚和一个或多个接收引脚连在一起。层次路径能帮你回到它服务的模块。
LEF
技术 LEF 说明金属层与布线规则。宏 LEF 给模板的尺寸、允许的对称性、引脚金属形状和障碍 OBS。把引脚当几何图形来读，别只看它的名字。
DEF 或布局数据库
给这颗芯片里的实例、坐标、朝向、放置状态，还有芯片边界、行等。可用的 core 区域在 die 内，实际可摆区域还会被行、围栏和障碍切掉。
Liberty（.lib）与 SDC
前者描述延时、功耗和约束弧，后者给本设计的时钟、I/O 延时与路径例外。判断关键路径需要它们。
GDS / OASIS，SPEF，供电意图
前两种版图格式保留实际图形；SPEF 提供提取的线电阻、电容；电源域、供电网络与电压要求限制可放的位置和可接的供电轨。

先算一次单位

如果 DEF 写着每微米 2,000 DBU（数据库单位），坐标 13,920 DBU 就是 6.96 µm。尺寸来自库，坐标来自实例。读到的“原点”还要按文件语义及朝向转换到统一坐标系。

第 05 课　/　第一次摆盘

先画谁和谁通信

A、B 两块 SRAM 几何完全一样，为什么不能随便交换？

回到那块缓存。把控制器标为 C，取两颗数据 SRAM 标为 A、B。读 A 要带过去地址和使能，还要把数据带回来。A 和 B 虽然相同，但如果 A 连的是 C，B 连的是另一个端口，它们适合的位置就可能不同。

从上千条网读出接口

  1. 从 A 的数据、地址及控制 pin 出发，沿网表找到另一端。经过组合逻辑时，必要时追到寄存器或模块边界。
  2. 把端点按控制器、总线、计算单元或 I/O 分组。分别记录位宽、方向、层次和是否处于关键路径。把时钟、复位等全局网络单独看。
  3. 叠加这些组粗摆后的物理位置。连接密切的端点如果隔着障碍，画出可能穿过的通道。

第一次试摆可以让 A 的数据引脚朝 C。但若两者之间隔着不能跨越的低层金属障碍，几何上近也可能绕远。第一版摆法是一条待验证的假设。

为什么不能简单数“连了几根线”？

64 位数据总线在物理上可占许多轨道。另一方面，一条低扇出控制路径也可能决定时钟周期。先分别看布线需求和时序重要性，再决定是否加权。

层次设计练习：顶层看不到里面的 SRAM 怎么办？

假设 CPU 子块已经硬化，右边一束接口访问外部 L2。先画 CPU 外部 pin 到 L2 pin 的通路，再画其他穿过这条走廊的总线。若热点在 CPU 内部，应带内部网表分析。若分区可改，比较调整边界 pin、让控制器与存储同组或拆分拥挤接口的代价；重新生成边界时序模型，再验证顶层。

第 06 课　/　第一次摆盘

先划出真正能摆的区域

看着空的地方，为什么可能放不下？

先在图上描出 die（整片边界）与 core（核心实现区），再叠加固定宏、I/O、禁止摆放区和电源域围栏。候选点只说明宏的一个锚点在那里，合法性必须检查放下后的整个轮廓。

把 A 放下去之前

  1. 把朝向作用于模板，算出实例外框和引脚坐标；若允许 90° 旋转，宽高会交换。
  2. 查整个外框是否位于可用区域，是否越过凹边、碰到固定障碍、已有宏或工艺要求的间隔。
  3. 查电源域、网格、朝向和明确的 keepout。halo 是周围留出的限制区，限制对象可能是标准单元、另一颗宏或某种布局阶段，要读当地定义。

例如 core 的 x 范围是 0–100 µm，A 宽 18 µm，左下角取 85 µm，右边界就到 103 µm。锚点合法，整颗仍越界。

即使芯片上空白总面积大于 A，碎成几个窄条也放不进它。评估利用率时写明分母，区分全 core 面积和扣掉固定块后的可摆面积。

进阶：计算真正能用的白地

100 × 100 µm 的 core，宏与禁止标准单元摆放区的并集占 4,000 µm²，标准单元面积为 4,200 µm²。以余下的 6,000 µm² 为分母，有效利用率为 70%。两个 halo 相交只扣一次。相同的 70% 可以是一片连续空间，也可以是窄缝，仍需检查局部密度和可用的单元行。

第 07 课　/　第一次摆盘

引脚朝向与通道的实际宽度

翻转一块 SRAM，中心不动，为什么还能改变结果？

Ariane 的模板里，w_mask_in[0] 的矩形在 metal3 的左边缘。对这颗宏用 FN 朝向会左右翻转，该引脚就到右边。两颗矩形的中心距离完全相同，控制器到引脚的距离和出线方向却变了。

估一条通道，先看哪一层

假设某层跨通道可用宽度为 4.0 µm，轨道节距为 0.4 µm，粗估约 10 条轨道。供电和障碍占去 3 条后，只剩约 7 条。如果这一层有 12 条线都得经过，已有约 5 条的缺口。精确数量依赖轨道起点、边界间隔、首选方向和过孔。

实际判断要分别查水平、垂直方向，确认哪些层能越过宏，哪些层被 OBS 阻断。引脚一侧可能需要留足打孔和扇出空间，背面则可能允许更紧密地贴放。翻转前再核对 LEF 对称性、供电轨和项目许可。

工程师怎样做第一版

在一片空 core 上，手第一步落在哪里？

先摆最不自由的对象。画出 I/O 和电源域，圈出不能动的 IP，再找接口强、长宽受限的那组 SRAM。挑两个都合法的方案，把标准单元粗摆进去后再看拥塞和关键路径。

一个有作者解释的选择

EagleX 团队在相邻计算 tile 边界镜像摆放，使向量单元和 L1 SRAM 可以贴合，给狭长 tile 留横向空间。同一颗芯片的脉动阵列内，工程师却把 SRAM 拉开，给下方和左侧的处理单元留走线空间。决定间距的是这条接口需要什么。

把人的经验写成可复用的约束

STAC 的工程师指定一组 SRAM 从左下角向上排。第一颗锚定在边上，后续读上一颗的实际边框，再加间隔。另一组则从左上向下排并使用另一种朝向。一个人做了分组与方向选择，程序替他展开坐标。

历史上这几种方式长期并存。2007 年的 MP-tree 已经自动搜索宏布局；2021 年 Google 仍以工程师多轮迭代的 TPU 布局作为基线。不同项目没有统一的人工占比。

第 09 课　/　验证摆放

给一次试摆算账

A 比初始位置近了，能说明新盘面更好吗？

先记硬约束，有重叠、越界或电源域错误的方案先淘汰。剩下的合法方案用一张账单比较。位移告诉你扰动多大；线长、拥塞和时序各回答不同问题。

位移
A 从 (10, 4) 到 (13, 2)，曼哈顿位移是 |3| + |−2| = 5。整盘可以报总和、最大值和移动宏数。单独记录翻转，因为纯翻转的中心位移可以是零。
HPWL，半周长线长
一条网的估计线长是引脚包围盒的宽加高。引脚在 (1,1)、(4,1)、(4,3)，HPWL 为 3 + 2 = 5。它计算很便宜，但看不到绕障、跨层和多端网的具体分支。
时序与可布性
关键路径是否变差、水平或垂直是否超容量、详细布线能否接到每个 pin，都要另查。解码失败和留大片碎白也应单独记录。

如果合成一个 cost，先统一方向与尺度。例如对同一设计的参考盘面，分别用固定正标尺归一化各项，再加权。参考 overflow 若为 0 就不能拿它当除数。保留原始单位，以便知道总分下降到底换来了什么。

第 10 课　/　验证摆放

读懂一格 overflow

热图上红了一块，红的究竟是什么？

全局布线常把芯片划成格子，相邻格子之间是一条可跨越的边。某层、某方向的一条边能容纳 C 条等效轨道，计划通过的需求为 D，边的 overflow 定为 max(0, D − C)。工具的显示可能把多条边、多层合到一个像素，先看单位和聚合方式。

例：边甲 D=12、C=8，边乙 D=7、C=8。两条边合计 overflow 为 4，最坏边也是 4。乙的空余不能自动抵消甲的超载。若 C=0，要单独处理利用率 D/C，超载量定义仍可计算。

红格有两个来源

需求集中。许多数据网引脚朝向同一条走廊，或综合逻辑本身连线密。供给减少。低层被宏、供电条带、过孔阵列或障碍占掉。某颗宏即使不连红格上的那些网，也可能挡住它们。

RUDY 是一种早期估计，把各网估计的布线需求分摊到其引脚包围盒内。它能提示哪里可能挤，无法给出某条网实际经过哪一格。你们的 myrudy 目前只是模型名，先明确定义输入、方向、容量和输出，再谈怎样接入 pack。

自己写估计器时，怎样处理直线和更新？

对宽 w、高 h 的二端包围盒，一种教学近似是将水平需求 w、垂直需求 h 分开按各格重合面积分配。宽或高为零时改用一维线段与格子的重合长度，或定义最小覆盖宽度，再检查需求守恒。移动引脚后，对受影响网撤销旧贡献、加入新贡献；障碍移动还要更新容量。用整盘重算作对照。

第 11 课　/　验证摆放

动手改变走线瓶颈

原地翻转、移走挡路的宏，两种动作的代价一样吗？

从四颗 SRAM 中取 A、B，在一片 12 × 8 的教学网格上试摆。A、B 都能移动和左右翻转。C 是固定的控制器端点，W、E 是总线两端，P 是固定 IP。先预测，再按按钮。

先完成三个动作

  1. 保留初始位置，看横穿 core 的 W–E 总线与 A 的数据线在哪里相遇。先只翻转 A，观察位移和超载分别怎么变。
  2. 恢复初始盘，把 A 下移一格。注意 A 有两格高，可能仍覆盖原通道。再下移一格，观察哪个指标发生变化。
  3. 让总 overflow 降到 0，同时总位移不超过 2 格。把自己的判断记到末课的实验记录里。

本实验的三条线束固定先水平后垂直，局部容量由宏遮挡决定。这使每条边的结果可以手算。真实全局路由器还会选路、分层、绕障和迭代消解拥塞。

从粗摆走到签核

全局布线不红了，为什么芯片仍可能过不了？

  1. 宏布局与标准单元粗摆。先找结构性问题。固定标准单元做对照时要说明；生产流程若允许重摆，须再评估一次合法化和粗摆后的反馈。
  2. 时钟树与时序。用约束和库评估路径。对 setup，slack 是要求到达时刻减实际到达时刻。要求 1.00 ns、实际 1.08 ns，余量 −0.08 ns。hold 用最早到达约束单独分析。比较同一角、同一模式及同一实现阶段的 WNS（最差负余量）和 TNS（负余量汇总）。
  3. 供电与特殊网络。检查宏 PG pin 能否接到正确电源域和条带，局部 IR drop、电流密度及噪声是否可接受。给信号留出的缝也可能是供电必经位置。
  4. 全局与详细布线。全局路由确定大致走廊，详细路由落实到轨道和过孔。没有全局 overflow，仍可能发生宏边 pin access 失败、间距 DRC 或短路。
  5. 提取与签核。用提取寄生重看多模式多工艺角的 setup/hold，检查 DRC、LVS（版图和网表是否一致）、电源完整性。根据项目阶段调用相应签核工具。

如果一翻 A 就改善拥塞却破坏供电引脚连通，先排除这个朝向；给代价函数再加一个小罚分不能替代这条硬约束。

时序实例：线短了，路径为什么还差？

检查同一模式与角下的起点、终点、单元弧和线延时。若要求 1.00 ns，改动前到达时间 1.08 ns，改后 1.05 ns，slack 就从 −0.08 变为 −0.05 ns。路径改善但仍未闭合。若瓶颈是 SRAM 内部访问弧，继续挪位置的空间有限；若主要是最后一段线与大扇出，就检查驱动、缓冲和引脚侧。

多电源域和模拟宏的落点怎样评审？

叠加电压域围栏、宏供电引脚、供电轨和连接金属层，查翻转后是否仍能接通。跨域接口要查电平转换和隔离单元的位置。对 PLL 等模拟块，用 IP 集成约束核实噪声隔离及其与参考时钟、供电的关系。把同一份候选数据库交给时钟、供电和布线负责人复查。

人在摆，算法在搜什么

从贪心到 RL，有哪些不同决定？

把当前题目写成五行：可移动对象、合法动作、硬约束、评价依据、停止条件。人把哪些动作交给机器，是比算法名字更重要的设计选择。

贪心和前瞻
贪心选眼前最好的候选。前瞻先临时摆后几颗，再评价首步。如果 A 占了 B 唯一能放的宽槽，第二步就能暴露眼前高分的代价。束搜索每层留若干条部分方案，代价随束宽上升。
树表示与模拟退火
树可以编码相对次序和贴靠关系，由解码器生成坐标。MP-tree 给出处理混合尺寸宏的打包表示。模拟退火可更改树、顺序或朝向，按温度有概率接受暂时变差的合法盘面。树是表示方法，退火是搜索方法。
解析布局与层次化
连续优化用可微近似权衡线长和密度，再做宏合法化。层次化方法先按连接或设计层次分组，再细化组内位置。分组过粗会漏掉跨组关键接口。
Q-table 与学到的策略
Q(s,a) 估计状态 s 下选动作 a 的后续回报。如果局面表示过细，训练中大量状态只见一次，旧 Q 值就很少参与下一次选择；规则筛选与前瞻仍可能起作用。要单测历史 Q 对选动作有多少贡献。

比较方法时固定初始盘、冻结对象、候选生成器和计算预算。记录合法出解率、质量分布和耗时；一次跑出好解不足以说明谁普遍更强。

怎样缩小巨大的状态空间？

假设 20 个宏各只有 8 个落点，忽略重叠也已有 8²⁰ 种组合。可以先固定部分宏、把同 bank 的几颗编成一组、只生成贴边或角落候选、按剩余空白剪枝，再对少数候选前瞻。每个限制都可能丢掉好解。在小例子上一次放开一种剪枝，测出速度换掉了多少好候选。

试摆 A 时，movement 和拥塞应该在何处比较？

用你们已经展开的 C++ 文本定位主线。getPackMacroOrder() 调用训练入口；在 multitrain() 的循环里能找到 multiActionLookAhead()。后者调用 multiStateLoop()，其中可以定位 getLoopActs()、getBestAct() 和 findFitBin()。恢复文本有 OCR 错字，函数名适合导航；具体参数、分支和权重要以团队可编译源码核对。

把动作和实际落点区分开

假设候选是 512 和 513。先确认它们表示 bin、方向还是一个已确定且合法的位置。若两个动作直到试放才知道 A 的实际坐标，单在候选排序时给精确位移或拥塞打分，就要先有与试放一致的几何结果。

  1. 候选阶段。可以先用便宜的位移下界或局部拥塞估计排序。记录被过滤掉的候选，避免把好解提前剪掉。
  2. 得到试摆盘面。对相同的候选状态算 Δmovement、Δmyrudy。局部已摆宏之外的端点用何种参考位置要固定。试摆撤回时同时恢复几何、需求和容量缓存，避免同一动作因评估顺序而得不同分数。
  3. 完整盘面。比较被接受的最终布局，跑同一评估器；早期局部奖评分和最终目标分别留日志。若模型高度相关却选错最好的候选，还需看候选排序。

实验日志可以只追一个宏。记下状态键、候选、试摆前后坐标、成本各项、有没有查到旧 Q、最终选了谁。这比盯着一次更新出的 1.4 更能定位贡献。

第 16 课　/　工程决策

拥塞后处理怎样选宏

摆盘已经完整，第一批该抠哪几颗？

  1. 先给原盘建基线。锁定网表、初始布局和固定对象。记录每层每方向的 overflow、最坏边、总量和时序。选一片相连的热点，并保留周围几圈边。
  2. 追需求，也追容量。有全局路由路径时，找哪些网跨过这些边，再追到端点宏和服务逻辑。只有 RUDY 时，将其标为估计贡献。另找直接覆盖瓶颈、压缩通道或限制可用落点的宏。
  3. 构造小组。分别尝试端点宏、挡路宏、同 bank 邻居。按可移动性、关键时序和可用目的地筛选。给不能动的标准单元或宏明确保护策略。
  4. 抠下并重建。在副本中移除选中的宏，重跑局部 pack 或枚举可行重摆。改变位置、组序或允许的朝向；其余对象按实验契约固定。检查归位、无重叠与约束。
  5. 决定保留或回退。对完整新盘做相同的验证。原热点降了仍需看全片总量、最坏边、位移与时序。如新热点更严重，回退并换一组。若换组也无效，检查容量模型或标准单元侧原因。

Splash2 的实际复盘里，一个热点来自用组合门实现的 FFT 旋转因子 ROM。作者提出给逻辑更大的摆放区域。对一个只能搬宏的后处理器，这说明“有红就必须搬某颗 macro”并非总有可行答案。

追因样例：这次到底搬谁？

同一条边基线 D=12、C=8，超 4。翻转端点宏 A 后估计 D=9、C=8，超 1。另一版移开未连这些网的宏 B 后，D=12、C=12，本边超 0。但若邻边新增 6 条 overflow，全片反而变差。两次都要等被抠的宏全部放回，再算完整盘面，否则临时消失的引脚与遮挡会美化结果。

随手查术语
bit、B、KiB
1 B（字节）等于 8 bit，1 KiB 等于 1,024 B。
Master 与 instance
Master 是库里的模板，instance 是这颗芯片里用到的一个具体副本。
Pin、port、net、bus
Pin 是实例上的引脚，port 常用于模块边界端口。一条 net 表示一个电连接，bus 是一组相关信号。
SRAM、bank、tag
SRAM 存比特，bank 是存储分区，tag 是缓存为辨认地址保存的标签。
标准单元、硬化、IP
标准单元是按行摆放的基础逻辑单元。硬化是把电路做成确定的物理版图。IP 是可复用的设计模块。
Floorplan、placement、routing
分别表示规划芯片及各区块、选择实例位置、在金属层连接引脚，工程中常来回迭代。
PDK、LEF、DEF
PDK 是工艺设计套件，LEF 提供技术与单元的物理抽象，DEF 描述一个具体设计的物理状态。
Track、via、OBS、halo
轨道是可走线的位置，过孔用于跨层，OBS 是挡住布线的图形。Halo 是外扩限制区，需要看它具体限制哪些对象。
HPWL、overflow、slack
分别衡量引脚包围盒半周长、超过容量的需求、时序余量。
CTS、PDN、ECO
时钟树综合、供电网络、工程变更。后期 ECO 往往限制扰动，并对受影响部分重新签核。
